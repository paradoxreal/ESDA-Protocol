Verify v1.1.0

Three checks you can run yourself: the download files match their published hashes, the code matches the release manifest, and that manifest is timestamped in the Bitcoin blockchain.

A timestamp proves the files existed by a certain time and haven't changed since. It says nothing about whether the code is secure. ESDA is research and teaching code: not independently audited, not constant-time.

2 · Check the code against the manifest

git clone https://github.com/paradoxreal/ESDA-Protocol
cd ESDA-Protocol
git show v1.1.0:stamps/ESDA_v1.1.0_MANIFEST.txt > /tmp/esda_manifest.txt
git checkout 800a1b0b6959a184cf647fa1f1aabf0daaeac8fe
grep -v '^#' /tmp/esda_manifest.txt | shasum -a 256 -c    # expect 18 lines ending in OK

Do this in a fresh clone. Running ./run.sh first rewrites esda_output.txt and the other result files, and then those four lines won't match.

3 · Check the Bitcoin timestamp

pip install opentimestamps-client
ots --no-bitcoin verify ESDA_v1.1.0_MANIFEST.txt.ots
# prints: check that Bitcoin block 975471 has merkleroot 4f179646…48b190dc
  1. Look up block 975471 in any block explorer, or on your own node with bitcoin-cli getblockheader $(bitcoin-cli getblockhash 975471).
  2. Its merkle root must equal 4f1796463fc1fc9d0618e595e95cd185ef5b55b7c88d7339911544e148b190dc.
  3. If you run a Bitcoin node, ots verify ESDA_v1.1.0_MANIFEST.txt.ots does both steps for you.

Keep the manifest and the .ots file together. Either one alone proves nothing.
